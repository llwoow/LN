## 基础概念题(FPGA结构、原理等)

基础概念题考查对FPGA内部结构与工作原理的准确理解,包括可编程逻辑块(CLB)、输入输出模块(IOB)、可编程互连资源、布线与配置存储等;存储资源方面需掌握块RAM(BRAM)与分布式RAM(DRAM,由LUT构成)的差异与适用场景;时钟管理模块方面需理解MMCM(混合模式时钟管理器)与PLL(锁相环)的特性与差异;复位策略则需区分同步复位、异步复位与异步复位同步释放的优缺点与适用条件。[^2][^4][^5]

在工程化设计中,资源选择与时钟/复位策略直接影响时序收敛与功耗。例如,少量数据缓存优先使用分布式RAM以降低布线和时序复杂度,大量数据缓存则应选择BRAM以获得更好的时序特性;对时序要求高的路径应优先使用BRAM并配合寄存器打拍;全局复位应采用异步复位同步释放以兼顾抗亚稳态与可控性。[^4][^5]

表5 FPGA主要资源类型与特性对比
| 资源类型 | 组成/实现 | 优点 | 缺点 | 典型应用 |
|---|---|---|---|---|
| IOB | 可编程输入/输出单元 | 接口灵活,支持多种电气标准 | 受器件封装与引脚限制 | 外部器件接口、板级通信 |
| 可编程逻辑块(CLB/LUT) | 查找表与触发器 | 实现组合与时序逻辑,灵活 | 深路径影响时序收敛 | 状态机、译码、计数器 |

|---|---|---|---|

## 编程题(VHDL/Verilog代码分析)

代码分析题考查对可综合语法与仿真语义的准确把握。Verilog方面,需关注敏感列表完整性、阻塞与非阻塞赋值的场景、锁存器与寄存器的区别、不可综合语句的识别与规避;VHDL方面,需掌握进程(PROCESS)结构、信号与变量的作用域与赋值语义、枚举类型与状态机建模。[^12][^4][^2]

锁存器推断是常见的扣分点。组合逻辑中if无else、case无default都会导致工具推断锁存器,影响时序与功耗。考试中,阅卷通常会检查敏感列表与分支完整性,并对不完整的条件描述进行扣分。表7总结了阻塞/非阻塞赋值的典型使用场景,表8给出不可综合语句的替代写法建议。

表7 阻塞与非阻塞赋值使用场景对照
| 场景 | 推荐赋值类型 | 说明 |
|---|---|---|
| 时序逻辑(触发器) | 非阻塞(<=) | 描述寄存器行为,避免竞争 |
| 组合逻辑 | 阻塞(=) | 描述组合逻辑的即时求值 |

## 设计题(状态机、计数器、译码器等)

设计题是体现“工程化编码与模块化思维”的主战场。状态机方面,需掌握两段式与三段式结构、Moore与Mealy型的输出时序差异,以及枚举类型与状态编码规范;计数器与分频方面,需关注同步/异步使能、进位链与占空比;译码器方面,需完成七段数码管的译码与动态扫描,确保位选与段选的时序配合。[^9][^1][^14]

在实现七段译码与动态扫描时,应将“译码模块”与“扫描模块”解耦,扫描时钟与显示时钟分离,通过位选信号实现多路复用。考试评分通常关注状态机结构清晰、复位与使能处理正确、仿真覆盖与时序关系正确、模块化与可读性良好。[^14][^9]

表9 状态机两段式 vs 三段式

| 可读性 | 较紧凑 | 结构清晰,便于维护 |
| 适用场景 | 简单状态机、输出对时序不敏感 | 复杂状态机、输出需稳定 |

## 时序分析计算题(建立/保持时间、Slack、STA)

时序分析题是拉分项,核心在于建立时间(Setup)与保持时间(Hold)的定义与裕量(Slack)计算。典型公式如下:  
- 建立需求:时钟周期 T_clk ≥ T_co + T_data + T_su − T_skew  
- 保持需求:T_h ≤ T_co + T_data − T_skew  
- 建立裕量:Slack_su = T_clk − (T_co + T_data + T_su − T_skew)  
- 保持裕量:Slack_h = (T_co + T_data − T_skew) − T_h  
其中,T_co为寄存器时钟到输出延迟,T_data为组合路径延迟,T_su为建立时间,T_h为保持时间,T_skew为时钟偏移。静态时序分析(STA)的基本流程为:施加约束(时钟、输入/输出延迟)→ 综合与实现 → 报告解读(路径分析、违例定位)→ 修复与验证(改逻辑、pipeline、布局优化)。[^3][^11]

考试中,考生需从给定路径参数计算出Slack并给出是否满足时序的判断,同时提出合理的修复方案。答题规范包括:列公式、替换参数、给出数值结果与结论、提出至少一种修复路径。[^3][^11]

表11汇总了时序参数与公式,表12给出了典型违例的修复策略。

表11 时序参数与公式汇总
| 符号 | 定义 | 公式/说明 |
|---|---|---|
| T_clk | 时钟周期 | 约束输入,决定频率 |
| T_co | 寄存器C→Q延迟 | 器件特性,影响Launch→Capture |
| T_data | 组合路径延迟 | LUT/布线延迟之和 |
| T_su | 建立时间 | 数据需提前稳定 |
| T_h | 保持时间 | 数据需滞后稳定 |
| T_skew | 时钟偏移 | Launch与Capture时钟边沿差 |
| Slack_su | 建立裕量 | >0才满足时序 |
| Slack_h | 保持裕量 | >0才满足时序 |

表12 典型时序违例与修复策略
| 违例类型 | 症状 | 修复策略 |
|---|---|---|
| 建立时间违例 | Slack_su < 0 | 缩短组合逻辑(流水线/拆分)、提高时钟质量、降低负载、优化布局 |
| 保持时间违例 | Slack_h < 0 | 增加延迟(插寄存器/缓冲)、优化时钟偏移、重新规划路径 |
| 亚稳态 | 不满足T_su/T_h或恢复时间 | 同步器(两级触发器)、异步FIFO、握手 |

## 资源计算题(LUT/FF/BRAM/DSP/IOB)

资源计算题考查对器件资源的估算与设计取舍。估算方法通常从位宽、深度与并行度出发,结合模块级联与资源共享策略进行;BRAM与分布式RAM的选择依据容量与时序要求;DSP Slice用于乘加类运算以降低逻辑占用并提升时序;IOB与布线资源受封装与引脚分配影响,需在约束文件中明确。[^4][^5]

表13给出BRAM与分布式RAM的对比,表14给出主要资源的估算思路。

表13 BRAM vs 分布式RAM对比
| 项目 | BRAM | 分布式RAM(DRAM) |
|---|---|---|
| 容量粒度 | 以块为单位(较大) | 由LUT构成,灵活 |
| 时序特性 | 时钟驱动,时序友好 | 组合/时序均可,受LUT影响 |
| 占用资源 | 占用整块,粒度较粗 | 占用LUT,可能影响其他逻辑 |
| 适用场景 | 大容量存储、FIFO | 小容量、寄存器文件 |
| 建议 | 大量数据优先BRAM | 少量数据优先DRAM |

表14 主要资源估算要点
| 资源 | 估算依据 | 典型场景 |
|---|---|---|
| LUT | 组合逻辑复杂度、位宽 | 译码、选择、运算 |
| FF | 寄存器数量、流水线级数 | 状态机、计数器、缓存 |
| BRAM | 深度×位宽、端口数 | 异步FIFO、帧缓存 |
| DSP | 乘加/滤波/FFT | 算法加速 |
| IOB | 引脚数与电气标准 | 外部接口 |
| 布线 | 模块互连密度 | 时钟网络与跨域路径 |

在答题时,应给出计算过程与取舍理由,并指出可能的瓶颈(如BRAM粒度导致的使用浪费、分布式RAM占用LUT影响时序),体现工程化思维。[^4][^5]

## 故障诊断与调试(常见错误与定位)

工程化能力在故障诊断与调试题中体现为“问题定位—证据—修复”的闭环。常见错误包括:异步逻辑导致亚稳态、未使用厂商原语(如xpm-cdc、BUFR)、未充分利用DSP Slice、锁存器推断、命名约定不统一、滥用复位、缺少DRC检查、仿真设置不当等。定位方法包括阅读综合/实现报告、运行DRC检查、分析时序报告、查看仿真波形与RTL-debug视图。[^5][^4][^12]

表15将常见错误与症状、定位方法与修复建议进行对照。

表15 常见错误-症状-定位方法-修复建议
| 错误 | 症状 | 定位方法 | 修复建议 |
|---|---|---|---|
| 异步逻辑/亚稳态 | 不稳定采样、随机错误 | STA违例、时序报告 | 同步器(两级触发器)、异步FIFO |
| 未用厂商原语 | 时钟/CDC实现低效 | 工具日志与建议 | 使用xpm-cdc、BUFR等原语 |
| 未用DSP Slice | 逻辑占用高、时序难收敛 | 资源报告 | 将乘加类映射至DSP |
| 锁存器推断 | 毛刺、功耗上升 | RTL检查、警告 | 补全if/else或case/default |
| 命名约定缺失 | 代码可读性差 | 代码审查 | 统一i_/o_/s_/c_/g_前缀 |
| 滥用复位 | 面积/功耗增大 | 资源与功耗报告 | 减少不必要复位,局部复位 |
| 缺DRC检查 | 隐患遗留至后期 | DRC报告 | 综合/实现后强制DRC |
| 仿真设置不当 | 调试低效 | 仿真日志 | 记录必要信号,合理建模 |

调试策略强调“阶段门禁”:综合后检查警告与DRC、实现后分析时序与资源、仿真阶段确保激励覆盖与信号可观测。答题时,应展示从“症状→定位→修复”的完整链条。[^5][^4][^12]

## 实践示例:典型设计的完整代码(Verilog/VHDL)

为帮助学习者理解和模仿,本节提供5个典型设计的完整代码示例,覆盖状态机、计数器与FIFO三类高频考点。每个示例包含模块声明、关键逻辑与简要说明,并附上仿真提示与工程要点。

### 示例1:Mealy型序列检测器(Verilog,重叠/非重叠可配置)

功能描述:检测输入序列中的特定模式(如“1101”),Mealy型输出与当前状态与输入相关。可通过参数配置支持重叠或非重叠检测。

```verilog
module seq_detect_mealy #(
  parameter PATTERN = 4'b1101,
  parameter OVERLAP = 1'b1  // 1:重叠允许,0:不允许重叠
)(
  input  wire clk,
  input  wire rst_n,
  input  wire in_bit,
  output reg  flag_detect
);

  localparam S0 = 3'b000, S1 = 3'b001, S2 = 3'b010, S3 = 3'b011, S4 = 3'b100;
  reg [2:0] cs, ns;

  always @(posedge clk or negedge rst_n) begin
    if (!rst_n) cs <= S0;
    else        cs <= ns;
  end

  always @(*) begin
    ns = S0;
    case (cs)
      S0: ns = in_bit ? S1 : S0;
      S1: ns = in_bit ? S2 : S0;
      S2: ns = in_bit ? S3 : S0;
      S3: ns = in_bit ? (OVERLAP ? S2 : S4) : S0;
      S4: ns = in_bit ? S2 : S0; // 仅用于非重叠时的吸收态
      default: ns = S0;
    endcase
  end

  always @(*) begin
    flag_detect = 1'b0;
    case (cs)
      S3: if (in_bit) flag_detect = 1'b1; // Mealy:输出依赖当前状态与输入
      S4: if (in_bit) flag_detect = 1'b1;
      default: ;
    endcase
  end

endmodule
```

仿真提示:构造随机输入序列,检查flag_detect的上升沿是否与目标模式对齐;对OVERLAP参数切换,验证重叠与非重叠行为的差异。工程要点:Mealy型输出可能存在毛刺,必要时可在输出端加寄存器打拍以提升时序稳定。[^9][^1]

### 示例2:三段式Moore型状态机(VHDL)

功能描述:Moore型状态机输出仅依赖当前状态,适用于输出需稳定的场景。以下为“序列检测Moore型”的参考实现。

```vhdl
library ieee;
use ieee.std_logic_1164.all;

entity moore_seq_detect is
  port (
    clk, rst_n : in  std_logic;
    in_bit     : in  std_logic;
    flag_detect: out std_logic
  );
end entity;

architecture rtl of moore_seq_detect is
  type state_t is (S0, S1, S2, S3, S4);
  signal cs, ns : state_t;
begin

  -- 段1:状态寄存器(时序)
  process (clk, rst_n) begin
    if rst_n = '0' then
      cs <= S0;
    elsif rising_edge(clk) then
      cs <= ns;
    end if;
  end process;

  -- 段2:下一状态逻辑(组合)
  process (cs, in_bit) begin
    ns <= S0;
    case cs is
      when S0 => if in_bit = '1' then ns <= S1; else ns <= S0; end if;
      when S1 => if in_bit = '1' then ns <= S2; else ns <= S0; end if;
      when S2 => if in_bit = '1' then ns <= S3; else ns <= S0; end if;
      when S3 => if in_bit = '1' then ns <= S4; else ns <= S0; end if;
      when S4 => if in_bit = '1' then ns <= S2; else ns <= S0; end if; -- 重叠允许
    end case;
  end process;

  -- 段3:输出逻辑(组合)
  flag_detect <= '1' when cs = S4 else '0';

end rtl;
```

仿真提示:在连续输入“1101”时,flag_detect在进入S4后的时钟周期拉高,稳定一个周期。工程要点:Moore型输出稳定但延迟一个时钟;状态枚举与case的完整性避免锁存器推断。[^9]

### 示例3:模N计数器(Verilog,参数化)

功能描述:基于50MHz系统时钟产生1秒与0.5秒的脉冲标志,实现LED每隔1秒翻转。参考野火实战指南的参数与位宽计算。[^14]

```verilog
module counter #(
  parameter CNT_MAX = 25'd24_999_999  // 0.5秒计数(50MHz)
)(
  input  wire sys_clk,
  input  wire sys_rst_n,
  output reg  led_out
);

  reg [24:0] cnt;
  reg        cnt_flag;

  always @(posedge sys_clk or negedge sys_rst_n) begin
    if (!sys_rst_n) cnt <= 25'b0;
    else if (cnt == CNT_MAX) cnt <= 25'b0;
    else cnt <= cnt + 1'b1;
  end

  always @(posedge sys_clk or negedge sys_rst_n) begin
    if (!sys_rst_n) cnt_flag <= 1'b0;
    else if (cnt == CNT_MAX - 25'b1) cnt_flag <= 1'b1;
    else cnt_flag <= 1'b0;
  end

  always @(posedge sys_clk or negedge sys_rst_n) begin
    if (!sys_rst_n) led_out <= 1'b0;
    else if (cnt_flag) led_out <= ~led_out;
  end

endmodule
```

仿真提示:将CNT_MAX设置为较小值(如25’d24)以加速仿真,观察led_out周期变化。工程要点:脉冲标志信号减少条件复杂度,提升可读性与时序;位宽需匹配计数最大值。[^14]

### 示例4:同步FIFO(Verilog,参数化)

功能描述:读写同一时钟的同步FIFO,使用循环指针与元素计数管理空满状态。参考工程化实现与端口定义。[^16]

```verilog
module sync_fifo #(
  parameter DATA_WIDTH = 32,
  parameter DATA_DEPTH = 8,
  parameter PTR_WIDTH  = 3
)(
  input  wire                     clk_i,
  input  wire                     rst_n_i,
  input  wire                     wr_en_i,
  input  wire [DATA_WIDTH-1:0]    wr_data_i,
  input  wire                     rd_en_i,
  output reg  [DATA_WIDTH-1:0]    rd_data_o,
  output reg                      full_o,
  output reg                      empty_o
);

  reg [DATA_WIDTH-1:0] mem [DATA_DEPTH-1:0];
  reg [PTR_WIDTH-1:0]  wr_ptr, rd_ptr;
  reg [PTR_WIDTH:0]    elem_cnt;

  always @(posedge clk_i or negedge rst_n_i) begin
    if (!rst_n_i) wr_ptr <= 3'b0;
    else if (wr_en_i && !full_o) begin
      mem[wr_ptr] <= wr_data_i;
      wr_ptr <= wr_ptr + 3'b1;
    end
  end

  always @(posedge clk_i or negedge rst_n_i) begin
    if (!rst_n_i) rd_ptr <= 3'b0;
    else if (rd_en_i && !empty_o) begin
      rd_data_o <= mem[rd_ptr];
      rd_ptr <= rd_ptr + 3'b1;
    end
  end

  always @(posedge clk_i or negedge rst_n_i) begin
    if (!rst_n_i) elem_cnt <= 4'b0;
    else if (wr_en_i && rd_en_i && !full_o && !empty_o) elem_cnt <= elem_cnt;
    else if (wr_en_i && !full_o) elem_cnt <= elem_cnt + 1'b1;
    else if (rd_en_i && !empty_o) elem_cnt <= elem_cnt - 1'b1;
  end

  always @(*) begin
    full_o  = (elem_cnt == DATA_DEPTH);
    empty_o = (elem_cnt == 0);
  end

endmodule
```

仿真提示:构造连续写入N个数据后连续读出,检查full/empty标志与数据顺序。工程要点:elem_cnt同时读写时的保持策略避免“读空/写满”误判;指针回绕需使用无符号宽度匹配。[^16]

| 时序计算 | 列出路径与参数 → 代入公式 → 计算Slack → 判断是否满足 → 提出修复(流水线/优化布局/同步器) |

| 调试题 | 症状描述 → 定位(报告/DRC/STA/波形) → 修复(原语/结构/约束) → 验证(复测与对比) |

信息缺口与处理建议:
- 各高校评分细则差异较大:建议采用本报告的通用权重模板,并在开考前由教师补充本校细则。
- 器件家族参数与时序数据:在计算题中以符号与范围作答,避免给出未经验证的绝对数值;课后结合官方手册完善。
- 完整真题文本:对受付费墙限制的文档,建议以题面摘要与考点映射替代,课堂提供示例工程。
- 综合与布局布线阈值:结合工具版本与器件手册,在实验课中建立“基线阈值表”,用于资源与时序的对比评估。
