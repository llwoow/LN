# 第三章 存储系统

## 3.1 存储系统概述

### 3.1.1 存储系统的层次结构

存储系统以层次结构统筹速度、容量与成本，形成典型的金字塔结构：

```
┌─────────────────────────┐
│     寄存器 (Registers)   │ ← 速度最快，容量最小
├─────────────────────────┤
│      Cache 高速缓存     │
├─────────────────────────┤
│     主存储器 (Memory)    │
├─────────────────────────┤
│     辅助存储器 (Disk)    │ ← 速度最慢，容量最大
└─────────────────────────┘
```

**🔥高频考点**：层次化设计的理论基础

### 3.1.2 局部性原理

**时间局部性**：近期访问的项可能再次被访问
- 程序循环中的变量
- 函数调用中的参数和返回值

**空间局部性**：临近地址的数据可能被连续访问
- 数组和顺序表的访问
- 顺序执行的指令序列

**💯必考内容**：局部性原理是Cache和虚拟存储设计的理论基石

### 3.1.3 存储器分类与特点

| 存储器类型 | 存储介质 | 访问方式 | 特点 | 典型应用 |
|------------|----------|----------|------|----------|
| **SRAM** | 触发器 | 随机访问 | 速度快，不需要刷新，成本高 | Cache |
| **DRAM** | 电容 | 随机访问 | 速度较慢，需要刷新，成本低 | 主存 |
| **ROM** | 掩膜/EPROM | 只读 | 非易失性，只读存储 | BIOS |
| **Flash** | 闪存 | 随机访问/块擦除 | 非易失性，可擦写 | 固态硬盘 |

**⚡易错点**：SRAM与DRAM的区分
- SRAM：静态随机存取存储器，以触发器存储信息，不需要刷新
- DRAM：动态随机存取存储器，以电容存储电荷，需要周期性刷新

## 3.2 主存储器

### 3.2.1 主存的基本结构

主存储器由存储体、地址译码器、读写控制电路和数据寄存器组成：

- **存储体**：由存储单元阵列组成
- **地址译码器**：将地址转换为字线选择信号
- **读写控制电路**：控制读写操作
- **数据寄存器(MDR)**：暂存读写数据

### 3.2.2 主存的扩展方式

**位扩展**：增加数据位宽
```
例如：4个1K×4位芯片 → 1K×16位存储器
```

**字扩展**：增加存储单元数量
```
例如：4个1K×8位芯片 → 4K×8位存储器
```

**字位同时扩展**：既增加位宽又增加容量
```
例如：8个1K×4位芯片 → 4K×8位存储器
```

### 3.2.3 主存性能指标

**访问时间(Access Time, Ta)**：从发出请求到数据开始输出的时间

**存取周期(Cycle Time, Tm)**：完成一次完整读写操作所需的总时间

**带宽(Bandwidth, Bm)**：单位时间内传输的数据量

$$Bm = \frac{W}{Tm}$$

其中：
- W：每次传输的数据位数
- Tm：存取周期时间

**🎯计算重点**：主存带宽计算

**示例**：
某主存周期时间 Tm = 10 ns，每次传输 64 位(8B)
$$Bm = \frac{64 \text{ bit}}{10 \text{ ns}} = 6.4 \text{ Gbps} = 800 \text{ MB/s}$$

## 3.3 高速缓冲存储器(Cache)

### 3.3.1 Cache的基本原理

Cache是位于CPU与主存之间的高速小容量存储器，用于缓解CPU与主存之间的速度差。

**工作原理**：
1. CPU访问主存时，先检查Cache
2. 如果命中(Cache Hit)，直接从Cache读取
3. 如果未命中(Cache Miss)，从主存读取并调入Cache

### 3.3.2 Cache的映射方式

#### 1. 直接映射

**映射规则**：主存块 i 只能映射到Cache的块 j = i mod 2^c
- c：Cache索引位数

**地址结构**：
```
┌─────────────┬─────────┬─────────────┐
│   标记位    │  索引位  │   块内偏移   │
│   Tag       │   Index │   Offset    │
└─────────────┴─────────┴─────────────┘
```

**特点**：
- ✅ 硬件实现简单
- ✅ 访问速度快
- ❌ 冲突概率高

#### 2. 全相联映射

**映射规则**：主存块可以映射到Cache的任意块

**地址结构**：
```
┌─────────────┬─────────────┐
│    标记位    │   块内偏移   │
│     Tag     │    Offset   │
└─────────────┴─────────────┘
```

**特点**：
- ✅ 命中率最高
- ❌ 硬件实现复杂
- ❌ 访问速度慢

#### 3. 组相联映射

**映射规则**：主存块映射到Cache的特定组，组内采用全相联方式

**地址结构**：
```
┌─────────────┬─────────┬─────────────┐
│    标记位    │  组索引  │   块内偏移   │
│     Tag     │  SetIdx │    Offset   │
└─────────────┴─────────┴─────────────┘
```

**特点**：
- ✅ 平衡了冲突概率与实现复杂度
- ✅ 现代处理器广泛采用

### 3.3.3 替换策略

当Cache已满且需要调入新块时，需要选择哪个块被替换：

| 替换策略 | 原理 | 优点 | 缺点 | 命中率 |
|----------|------|------|------|--------|
| **随机(RAND)** | 随机选择 | 简单 | 不考虑局部性 | 中 |
| **先进先出(FIFO)** | 替换最早进入的块 | 简单 | 可能发生Belady现象 | 中 |
| **最不经常使用(LFU)** | 替换访问次数最少的块 | 考虑频率 | 统计开销大 | 中-高 |
| **最近最少使用(LRU)** | 替换最近最久未访问的块 | 接近最优 | 实现复杂 | 高 |

**💯必考内容**：LRU算法的实现与性能分析

### 3.3.4 Cache性能分析

#### 命中率与平均访问时间

**命中率(Hit Rate, h)**：
$$h = \frac{\text{命中次数}}{\text{总访问次数}}$$

**未命中率(Miss Rate, mr)**：
$$mr = 1 - h$$

**平均访问时间(AMAT)**：
$$AMAT = h \times t_c + (1-h) \times t_m$$

其中：
- t_c：Cache访问时间
- t_m：主存访问时间

<details>
<summary><strong>📐 AMAT公式详细推导</strong></summary>

**基本假设**：
- H = 命中率（Hit Rate）
- MR = 未命中率（Miss Rate）= 1 - H
- HT = 命中时间（Hit Time）
- MP = 未命中惩罚（Miss Penalty）

**平均访问时间推导**：

平均访问时间 = 命中情况的时间 + 未命中情况的时间
= H × HT + MR × (HT + MP)
= H × HT + (1-H) × (HT + MP)
= HT + (1-H) × MP

由于HT是常数，提出来后得到：
AMAT = HT + MR × MP
</details>

#### 多级Cache的AMAT

对于两级Cache系统（L1和L2）：

$$AMAT = HT(L1) + MR(L1) \times [HT(L2) + MR(L2) \times MP(L2)]$$

**本地与全局未命中率**：
- 本地未命中率：在该层缓存中的未命中次数 ÷ 对该层缓存的访问总次数
- 全局未命中率：缓存未命中次数 ÷ CPU发出的总内存访问请求次数

对于两级Cache：
- 全局L2未命中率 = MR(L1) × MR(L2)

### 3.3.5 Cache的写策略

**写直达(Write-Through)**：
- 写入Cache的同时写入主存
- ✅ 保持Cache与主存一致性
- ❌ 写操作速度慢

**写回(Write-Back)**：
- 只写入Cache，当块被替换时才写回主存
- ✅ 写操作速度快
- ❌ 需要额外的修改位(Mirty Bit)

**💯必考内容**：写策略对系统性能的影响分析

## 3.4 虚拟存储器

### 3.4.1 虚拟存储器的基本概念

虚拟存储器通过页式/段式/段页式管理，将主存与辅存统一为更大的逻辑地址空间。

**主要功能**：
- 扩大地址空间
- 实现进程隔离
- 提供地址保护
- 支持程序的重定位

### 3.4.2 地址映射机制

#### 页式管理

**地址结构**：
```
┌─────────────┬─────────────┐
│   虚页号     │   页内偏移   │
│    VPN      │    Offset   │
└─────────────┴─────────────┘
```

**地址转换过程**：
1. CPU生成虚拟地址
2. MMU查找页表
3. 根据虚页号找到物理页框号
4. 合成物理地址

**页表项结构**：
```
┌─┬─┬─┬─────────────┐
│P│U│M│  物理页框号  │
└─┴─┴─┴─────────────┘
│ │ │
│ │ └── 修改位(Dirty Bit)
│ │──── 使用位(Reference Bit)
│────── 有效位(Valid Bit)
```

#### 段式管理

**地址结构**：
```
┌─────────────┬─────────────┐
│   段号      │   段内偏移   │
│    SN      │    Offset   │
└─────────────┴─────────────┘
```

**段表项结构**：
```
┌─────────────┬─────────────┬─────────────┐
│   段基址     │   段长度     │   保护信息   │
└─────────────┴─────────────┴─────────────┘
```

#### 段页式管理

结合段式和页式的优点：
- 先分段，再分页
- 地址结构：段号 + 页号 + 页内偏移

### 3.4.3 TLB(转换检测缓冲区)

TLB是用于加速虚拟地址到物理地址转换的Cache：

**TLB与Cache的区别**：
- TLB缓存页表项，用于地址转换
- Cache缓存实际的数据或指令，用于减少访存延迟
- 两者可并行工作

**地址转换流程**：
```
虚拟地址 → TLB查找 → 页表查找 → Cache查找 → 主存访问
```

<details>
<summary><strong>📐 虚拟地址转换详细过程</strong></summary>

**步骤1：TLB查找**
1. 从虚拟地址中提取VPN（虚页号）
2. 在TLB中查找对应的PTE（页表项）
3. 如果TLB命中，直接获得PPN（物理页框号）
4. 如果TLB未命中，转步骤2

**步骤2：页表查找**
1. 使用VPN索引页表
2. 从页表中获取PTE
3. 检查有效位、保护位等
4. 如果页面不在内存中，触发缺页中断

**步骤3：物理地址合成**
1. 将PPN与页内偏移合成物理地址
2. 进行Cache查找或主存访问

**步骤4：TLB更新**
1. 将新转换的页表项加载到TLB
2. 如果TLB已满，使用替换算法
</details>

### 3.4.4 页面置换算法

当发生缺页中断且内存已满时，需要选择页面换出：

| 置换算法 | 原理 | 优点 | 缺点 |
|----------|------|------|------|
| **OPT** | 置换未来最久不被访问的页面 | 最优 | 无法实现 |
| **LRU** | 置换最近最久未使用的页面 | 接近最优 | 实现复杂 |
| **FIFO** | 置换最早进入内存的页面 | 简单 | 可能Belady异常 |
| **Clock** | 近似LRU，环形队列 | 实现简单 | 性能一般 |
| **LFU** | 置换访问次数最少的页面 | 考虑频率 | 统计开销大 |

**💯必考内容**：LRU算法的近似实现（Clock算法）

## 3.5 磁盘存储器

### 3.5.1 磁盘的基本结构

磁盘由盘片、磁头、磁臂、主轴等部件组成：

**关键参数**：
- **记录面数(N)**：盘组中用于数据记录的面数
- **每面磁道数(T)**：每面的磁道数量  
- **每道扇区数(S)**：每条磁道的扇区数
- **每扇区字节数(B)**：每个扇区的字节数

### 3.5.2 磁盘容量计算

**格式化容量**：
$$C = N \times T \times S \times B$$

**非格式化容量**：
$$C_{raw} = N \times T \times \text{位密度} \times \text{磁道周长}$$

### 3.5.3 磁盘性能指标

**平均寻道时间(Ts)**：磁头移动到目标磁道所需的平均时间

**平均旋转延迟(Tr)**：等待目标扇区旋转到磁头下方的时间
$$T_r = \frac{1}{2} \times \frac{60}{\text{转速(RPM)}} \text{秒}$$

**传输时间(Tt)**：数据传输所需时间
$$T_t = \frac{\text{数据量}}{\text{传输率}} = \frac{\text{扇区数} \times \text{每扇区字节数}}{\text{转速} \times \text{每磁道扇区数} \times \text{每扇区字节数}}$$

**平均存取时间**：
$$T_a = T_s + T_r + T_t$$

**🎯计算重点**：磁盘平均存取时间计算

**示例**：
某磁盘转速7200 RPM，平均寻道时间8ms，传输4KB数据：
- 平均旋转延迟：Tr = 60/(2×7200) = 4.17ms
- 传输时间：Tt = 4KB / (7200RPM × 扇区数 × 4KB) ≈ 2ms
- 平均存取时间：Ta = 8 + 4.17 + 2 = 14.17ms

### 3.5.4 磁盘调度算法

当多个磁盘访问请求同时到达时，需要调度算法优化访问顺序：

| 调度算法 | 原理 | 优点 | 缺点 |
|----------|------|------|------|
| **FCFS** | 按请求到达顺序服务 | 公平 | 效率低 |
| **SSTF** | 选择最近的磁道 | 减少寻道时间 | 可能饥饿 |
| **SCAN** | 磁臂来回扫描 | 避免饥饿 | 边界延迟 |
| **C-SCAN** | 单向扫描 | 响应时间均匀 | 实现复杂 |
| **LOOK** | 智能扫描 | 减少不必要移动 | 算法复杂 |

**💯必考内容**：磁盘调度算法的性能分析与比较

## 3.6 存储器系统设计

### 3.6.1 存储系统设计原则

1. **容量匹配**：根据应用需求确定各层容量
2. **速度匹配**：相邻层次速度差异不能过大
3. **成本优化**：单位容量成本逐层递增
4. **可靠性保证**：数据完整性和系统稳定性

### 3.6.2 存储系统性能评估

**系统平均访问时间**：
$$T_{avg} = \sum_{i=1}^{n} h_i \times t_i$$

其中：
- h_i：第i层命中率
- t_i：第i层访问时间
- n：存储层次数

**存储层次效率**：
$$\eta = \frac{T_{fast}}{T_{avg}}$$

其中T_fast是最快层的访问时间。

### 3.6.3 存储系统优化策略

1. **增加Cache容量**：提高命中率，但增加成本和访问时间
2. **提高相联度**：减少冲突，但增加硬件复杂度
3. **优化替换算法**：提高命中率，但增加实现复杂度
4. **多级Cache**：平衡容量与速度，但增加设计复杂度

## 3.9 典型例题解析

### 例题1：Cache性能分析

**题目**：某系统L1 Cache容量为32KB，块大小为64字节，采用2路组相联映射。CPU执行某程序时，L1 Cache命中率为95%，L1 Cache访问时间为1个时钟周期，主存访问时间为100个时钟周期。求该程序在Cache子系统上的平均访问时间。

**解答**：
1. 计算Cache参数：
   - 块大小：64B → 块内偏移：log₂(64) = 6位
   - Cache容量：32KB = 2¹⁵B
   - Cache块数：32KB/64B = 512块
   - 组数：512/2 = 256组 → 组索引：log₂(256) = 8位
   - 标记位宽：32-8-6 = 18位

2. 计算平均访问时间：
   - AMAT = Hit_Time + Miss_Rate × Miss_Penalty
   - AMAT = 1 + (1-0.95) × 100 = 1 + 0.05 × 100 = 6个时钟周期

**答案**：平均访问时间为6个时钟周期。

### 例题2：虚拟存储管理

**题目**：某系统采用页式虚拟存储管理，页面大小为4KB，虚地址空间为4GB，物理内存为256MB。求：
1. 虚页号和页内偏移的位数
2. 页表项数
3. 物理页框数

**解答**：
1. 地址结构分析：
   - 虚地址空间：4GB = 2³²B → 总位数：32位
   - 页面大小：4KB = 2¹²B → 页内偏移：12位
   - 虚页号位数：32-12 = 20位

2. 页表项数 = 虚页号数量 = 2²⁰ = 1M项

3. 物理内存：256MB = 2²⁸B
   - 物理页框数：2²⁸/2¹² = 2¹⁶ = 64K个

**答案**：
1. 虚页号20位，页内偏移12位
2. 页表项数为1M项
3. 物理页框数为64K个

### 例题3：磁盘性能计算

**题目**：某磁盘驱动器参数如下：转速7200 RPM，每磁道63个扇区，每扇区512字节，平均寻道时间8ms。求读取一个4KB文件的最短和最长时间。

**解答**：
1. 基本参数计算：
   - 平均旋转延迟：Tr = 60/(2×7200) = 4.17ms
   - 每转传输时间：Tt_per_rev = 60/7200 = 8.33ms
   - 每扇区传输时间：Tt_per_sector = 8.33/63 = 0.132ms

2. 文件分析：
   - 文件大小：4KB = 4096B
   - 每扇区：512B → 需要8个扇区

3. 最短时间（连续扇区）：
   - 寻道时间：8ms
   - 旋转延迟：4.17ms
   - 传输时间：8 × 0.132 = 1.056ms
   - 总时间：8 + 4.17 + 1.056 = 13.226ms

4. 最长时间（跨磁道）：
   - 假设分布在8个不同磁道
   - 寻道时间：8 × 8 = 64ms
   - 旋转延迟：8 × 4.17 = 33.36ms
   - 传输时间：8 × 0.132 = 1.056ms
   - 总时间：64 + 33.36 + 1.056 = 98.416ms

**答案**：最短时间约13.23ms，最长时间约98.42ms。
