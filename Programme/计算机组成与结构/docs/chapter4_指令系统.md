# 第四章 指令系统

## 4.1 指令系统概述

指令系统是计算机硬件与软件之间的接口，是计算机体系结构设计的重要组成部分。它定义了计算机能够执行的所有操作以及这些操作的操作数来源和结果去向。指令系统的设计直接影响计算机的性能、编程便利性和实现复杂度。

### 4.1.1 指令系统的作用

🔥**高频考点**：指令系统的作用和地位
- **硬件-软件接口**：指令系统是计算机硬件直接能够识别和执行的所有命令的集合
- **软件基础**：所有软件都最终需要转换为指令系统中的指令才能在硬件上运行
- **性能决定因素**：指令系统的设计直接影响计算机系统的整体性能

### 4.1.2 指令系统的基本要求

- **完整性**：能够实现所有必要的操作
- **有效性**：指令执行效率高
- **规整性**：指令格式统一，规律性强
- **兼容性**：能够运行不同层次的程序

## 4.2 指令格式

指令格式决定了指令的结构，包括操作码字段和地址码字段的组织和位数分配。

### 4.2.1 指令的基本结构

指令通常由两部分组成：
- **操作码字段**：指定要执行的操作类型
- **地址码字段**：指定操作数的地址或操作数本身

### 4.2.2 指令格式分类

根据地址码字段的数量，指令格式可以分为以下几类：

#### 1. 零地址指令
```
┌─────────────┐
│    操作码    │
└─────────────┘
```
- **特点**：没有地址码字段
- **适用场景**：堆栈操作、空操作(NOP)、停机(HALT)
- **示例**：PUSH、POP、ADD(堆栈型计算机)

#### 2. 一地址指令
```
┌─────────┬─────────────┐
│  操作码  │    地址A     │
└─────────┴─────────────┘
```
- **特点**：只有一个地址码字段
- **适用场景**：单操作数运算，隐含累加器作为另一个操作数
- **示例**：INC A、DEC A、NOT A

#### 3. 二地址指令
```
┌─────────┬─────────────┬─────────────┐
│  操作码  │   地址A(源)  │  地址B(目的) │
└─────────┴─────────────┴─────────────┘
```
- **特点**：有两个地址码字段
- **适用场景**：双操作数运算
- **示例**：ADD A, B; MOV A, B

#### 4. 三地址指令
```
┌─────────┬─────────────┬─────────────┬─────────────┐
│  操作码  │  地址A(源1)  │  地址B(源2)  │  地址C(结果) │
└─────────┴─────────────┴─────────────┴─────────────┘
```
- **特点**：有三个地址码字段
- **适用场景**：复杂运算，结果单独存放
- **示例**：ADD A, B, C; SUB A, B, C

#### 5. 四地址指令
```
┌─────────┬─────────┬─────────┬─────────┬─────────┐
│  操作码  │ 地址A(源)│ 地址B(源)│ 地址C(结果)│ 下一条指令│
└─────────┴─────────┴─────────┴─────────┴─────────┘
```
- **特点**：有四个地址码字段，包括下一条指令地址
- **适用场景**：早期计算机，用于程序控制

### 4.2.3 指令格式设计原则

💯**必考内容**：指令格式设计的基本原则
1. **操作码长度固定**：便于译码和流水线处理
2. **地址码长度可变**：适应不同的寻址方式
3. **寄存器优先**：优先使用寄存器作为操作数
4. **扩展操作码**：充分利用指令编码空间

### 4.2.4 扩展操作码技术

**扩展操作码**是一种在指令字长固定的情况下，通过地址码字段的组合来增加操作码数量的技术。

**设计原则**：
- 短操作码不能是长操作码的前缀
- 操作码数量 = Σ(地址码组合数 × 对应的操作码数)

**示例**：设指令字长16位，地址码长度可变
- 零地址指令：操作码8位，最多256条
- 一地址指令：操作码6位，地址码10位，最多64条，每条可扩展出256条指令
- 二地址指令：操作码4位，地址码各6位，最多16条，每条可扩展出1024条指令

## 4.3 寻址方式

寻址方式是指令系统中用来指定操作数地址的方法，它直接影响指令的执行效率和程序的灵活性。

### 4.3.1 指令寻址

指令寻址用于确定下一条要执行的指令地址。

#### 1. 顺序寻址
- **原理**：程序计数器(PC)自动递增，指向下一条指令
- **适用场景**：顺序执行程序
- **计算公式**：PC ← PC + 指令长度

#### 2. 跳跃寻址
- **原理**：通过跳转指令修改PC值
- **适用场景**：程序分支、循环、函数调用
- **类型**：相对寻址、直接寻址、间接寻址

### 4.3.2 数据寻址

数据寻址用于确定操作数的有效地址(EA)。

#### 1. 立即寻址
```
┌─────────┬─────────────┐
│  操作码  │   立即数     │
└─────────┴─────────────┘
```
- **特点**：操作数直接包含在指令中
- **优点**：无需访存，执行速度快
- **缺点**：操作数长度受限，修改困难
- **有效地址**：EA = 指令中的立即数
- **适用场景**：常数赋值、初始化操作

#### 2. 直接寻址
```
┌─────────┬─────────────┐
│  操作码  │   地址A      │
└─────────┴─────────────┘
```
- **特点**：指令中直接给出操作数地址
- **优点**：简单直观
- **缺点**：地址范围受限，程序重定位困难
- **有效地址**：EA = A
- **适用场景**：简单数据访问

<details>
<summary><strong>📝推导过程</strong></summary>

**有效地址计算**：
对于直接寻址方式，有效地址就是指令中给出的地址A。

设指令格式为：
- 操作码字段：OP
- 地址字段：A

执行过程：
1. CPU从内存中取指令
2. 译码得到操作码OP和地址A
3. 有效地址EA = A
4. 根据EA访问内存获取操作数

数学表示：
$$EA = A$$

其中A是指令中直接给出的地址值。
</details>

#### 3. 间接寻址
```
┌─────────┬─────────────┐
│  操作码  │   地址A      │
└─────────┴─────────────┘
```
- **特点**：指令中给出的是操作数地址的地址
- **优点**：地址范围大，支持程序重定位
- **缺点**：需要多次访存，执行时间长
- **有效地址**：EA = (A)
- **适用场景**：复杂数据结构、动态内存分配

<details>
<summary><strong>📝推导过程</strong></summary>

**有效地址计算**：
间接寻址需要两次访存才能获得操作数。

设指令格式为：
- 操作码字段：OP
- 地址字段：A

执行过程：
1. CPU从内存中取指令
2. 译码得到操作码OP和地址A
3. 第一次访存：根据地址A读取内容，得到实际操作数地址
4. 有效地址EA = (A)
5. 第二次访存：根据EA访问内存获取操作数

数学表示：
$$EA = M[A]$$

其中M[A]表示内存地址A处的内容，括号表示间接寻址。

执行时间：需要2次内存访问周期。
</details>

#### 4. 寄存器寻址
```
┌─────────┬─────────────┐
│  操作码  │   寄存器R    │
└─────────┴─────────────┘
```
- **特点**：操作数在寄存器中
- **优点**：执行速度快，无需访存
- **缺点**：寄存器数量有限
- **有效地址**：EA = R
- **适用场景**：频繁访问的操作数

#### 5. 寄存器间接寻址
```
┌─────────┬─────────────┐
│  操作码  │   寄存器R    │
└─────────┴─────────────┘
```
- **特点**：寄存器中存放的是操作数地址
- **优点**：地址范围大，比内存间接寻址快
- **缺点**：需要一次访存
- **有效地址**：EA = (R)
- **适用场景**：指针操作、数组访问

<details>
<summary><strong>📝推导过程</strong></summary>

**有效地址计算**：
寄存器间接寻址通过寄存器中的值作为地址访问内存。

设指令格式为：
- 操作码字段：OP
- 寄存器字段：R

执行过程：
1. CPU从寄存器文件中读取寄存器R的内容
2. 有效地址EA = R的内容
3. 根据EA访问内存获取操作数

数学表示：
$$EA = Reg[R]$$

其中Reg[R]表示寄存器R的内容。

执行时间：需要1次内存访问周期，比内存间接寻址快。
</details>

#### 6. 相对寻址
```
┌─────────┬─────────────┐
│  操作码  │   位移量D    │
└─────────┴─────────────┘
```
- **特点**：以程序计数器(PC)为基址，加上位移量
- **优点**：位置无关代码，支持程序重定位
- **缺点**：位移量范围有限
- **有效地址**：EA = (PC) + D
- **适用场景**：分支指令、位置无关代码

<details>
<summary><strong>📝推导过程</strong></summary>

**有效地址计算**：
相对寻址以当前PC值为基准，通过位移量计算有效地址。

设指令格式为：
- 操作码字段：OP
- 位移量字段：D

执行过程：
1. CPU获取当前PC值（指向下一条指令）
2. 有效地址EA = PC + D
3. 根据EA访问内存获取操作数

数学表示：
$$EA = PC + D$$

其中PC是程序计数器当前值，D是带符号的位移量。

注意：PC值通常指向下一条指令，所以实际偏移量需要考虑指令长度。

执行时间：需要1次内存访问周期。
</details>

#### 7. 基址寻址
```
┌─────────┬─────────────┬─────────────┐
│  操作码  │   基址寄存器B │   位移量D    │
└─────────┴─────────────┴─────────────┘
```
- **特点**：以基址寄存器为基址，加上位移量
- **优点**：支持动态重定位，地址范围大
- **缺点**：需要基址寄存器
- **有效地址**：EA = (B) + D
- **适用场景**：多道程序设计、数组访问

<details>
<summary><strong>📝推导过程</strong></summary>

**有效地址计算**：
基址寻址使用基址寄存器的内容作为基地址，通过位移量计算有效地址。

设指令格式为：
- 操作码字段：OP
- 基址寄存器字段：B
- 位移量字段：D

执行过程：
1. CPU从寄存器文件中读取基址寄存器B的内容
2. 有效地址EA = B的内容 + D
3. 根据EA访问内存获取操作数

数学表示：
$$EA = Reg[B] + D$$

其中Reg[B]表示基址寄存器B的内容，D是位移量。

基址寄存器通常由操作系统管理，用于程序重定位。

执行时间：需要1次内存访问周期。
</details>

#### 8. 变址寻址
```
┌─────────┬─────────────┬─────────────┐
│  操作码  │   变址寄存器X │   位移量D    │
└─────────┴─────────────┴─────────────┘
```
- **特点**：以变址寄存器为变址量，加上位移量
- **优点**：适合数组和字符串处理
- **缺点**：需要变址寄存器
- **有效地址**：EA = (X) + D
- **适用场景**：数组访问、字符串操作、循环优化

<details>
<summary><strong>📝推导过程</strong></summary>

**有效地址计算**：
变址寻址使用变址寄存器的内容作为变址量，通过位移量计算有效地址。

设指令格式为：
- 操作码字段：OP
- 变址寄存器字段：X
- 位移量字段：D

执行过程：
1. CPU从寄存器文件中读取变址寄存器X的内容
2. 有效地址EA = X的内容 + D
3. 根据EA访问内存获取操作数

数学表示：
$$EA = Reg[X] + D$$

其中Reg[X]表示变址寄存器X的内容，D是位移量。

变址寄存器通常由程序员控制，用于实现数组索引。

执行时间：需要1次内存访问周期。
</details>

#### 9. 基址变址寻址
```
┌─────────┬─────────────┬─────────────┬─────────────┐
│  操作码  │  基址寄存器B  │  变址寄存器X  │   位移量D    │
└─────────┴─────────────┴─────────────┴─────────────┘
```
- **特点**：同时使用基址寄存器和变址寄存器
- **优点**：地址计算灵活，范围大
- **缺点**：需要两个寄存器，硬件复杂
- **有效地址**：EA = (B) + (X) + D
- **适用场景**：复杂数据结构、多维数组

<details>
<summary><strong>📝推导过程</strong></summary>

**有效地址计算**：
基址变址寻址结合基址寻址和变址寻址的优点。

设指令格式为：
- 操作码字段：OP
- 基址寄存器字段：B
- 变址寄存器字段：X
- 位移量字段：D

执行过程：
1. CPU从寄存器文件中读取基址寄存器B的内容
2. CPU从寄存器文件中读取变址寄存器X的内容
3. 有效地址EA = B的内容 + X的内容 + D
4. 根据EA访问内存获取操作数

数学表示：
$$EA = Reg[B] + Reg[X] + D$$

其中Reg[B]是基址寄存器内容，Reg[X]是变址寄存器内容，D是位移量。

这种寻址方式提供了最大的地址灵活性。

执行时间：需要1次内存访问周期。
</details>

#### 10. 隐含寻址
```
┌─────────┐
│  操作码  │
└─────────┘
```
- **特点**：操作数隐含在指令中，不在地址码中指定
- **优点**：指令短，执行快
- **缺点**：灵活性差
- **有效地址**：操作数在累加器(ACC)或其他隐含寄存器中
- **适用场景**：累加器型指令、栈操作

### 4.3.3 寻址方式对比表

| 寻址方式 | 有效地址计算 | 访存次数 | 优点 | 缺点 | 适用场景 |
|---------|-------------|---------|------|------|----------|
| 立即寻址 | EA = 立即数 | 0 | 执行快，无需访存 | 操作数长度受限 | 常数赋值 |
| 直接寻址 | EA = A | 1 | 简单直观 | 地址范围受限 | 简单数据访问 |
| 间接寻址 | EA = (A) | 2 | 地址范围大 | 执行慢 | 复杂数据结构 |
| 寄存器寻址 | EA = R | 0 | 执行最快 | 寄存器有限 | 频繁访问操作数 |
| 寄存器间接寻址 | EA = (R) | 1 | 地址范围大，比内存间接快 | 需要一次访存 | 指针操作 |
| 相对寻址 | EA = (PC) + D | 1 | 位置无关 | 位移量范围有限 | 分支指令 |
| 基址寻址 | EA = (B) + D | 1 | 支持重定位 | 需要基址寄存器 | 多道程序设计 |
| 变址寻址 | EA = (X) + D | 1 | 适合数组处理 | 需要变址寄存器 | 数组字符串访问 |
| 基址变址寻址 | EA = (B) + (X) + D | 1 | 灵活，范围大 | 硬件复杂 | 复杂数据结构 |
| 隐含寻址 | 操作数在ACC等 | 0 | 指令短 | 灵活性差 | 累加器操作 |

⚡**易错点**：
- 相对寻址的PC值是取指后的值
- 间接寻址需要两次访存
- 基址和变址寻址的寄存器内容不同

## 4.4 CISC与RISC技术

CISC(Complex Instruction Set Computer)和RISC(Reduced Instruction Set Computer)是两种不同的指令系统设计哲学。

### 4.4.1 CISC技术特点

**复杂指令系统计算机**追求指令系统的复杂性和完整性。

#### 主要特征：
- **指令数量多**：通常有200-300条指令
- **指令格式复杂**：变长指令，格式不规整
- **寻址方式丰富**：支持多种寻址方式
- **微程序控制**：大多数指令由微程序实现
- **单周期指令少**：指令执行时间不均匀

#### 优点：
- **编程效率高**：一条指令可完成复杂操作
- **代码密度高**：程序占用内存少
- **向后兼容**：支持历史软件生态

#### 缺点：
- **硬件复杂**：控制器设计复杂
- **执行效率低**：微程序执行速度慢
- **功耗大**：硬件复杂度高

#### 典型代表：
- Intel x86系列
- VAX系列
- IBM System/360

### 4.4.2 RISC技术特点

**精简指令系统计算机**追求指令系统的简洁性和高效性。

#### 主要特征：
- **指令数量少**：通常少于100条指令
- **指令格式规整**：定长指令，格式统一
- **寻址方式简单**：主要支持寄存器寻址
- **硬布线控制**：指令由硬布线逻辑实现
- **单周期指令多**：大多数指令在一个周期内完成

#### 优点：
- **执行效率高**：硬布线控制速度快
- **硬件简单**：控制器设计简化
- **功耗低**：硬件复杂度低
- **流水线友好**：规整指令格式利于流水线

#### 缺点：
- **代码密度低**：需要更多指令完成同样功能
- **编程复杂**：需要编译器优化
- **兼容性差**：与CISC系统不兼容

#### 典型代表：
- ARM系列
- MIPS系列
- RISC-V系列
- PowerPC系列

### 4.4.3 CISC vs RISC对比表

| 维度 | CISC | RISC |
|------|------|------|
| 指令数量 | 多(200-300) | 少(<100) |
| 指令长度 | 变长 | 定长 |
| 寻址方式 | 丰富(10+) | 简单(3-5) |
| 指令格式 | 不规整 | 规整统一 |
| 控制方式 | 微程序为主 | 硬布线为主 |
| 寄存器数量 | 少(8-16) | 多(32+) |
| 指令周期 | 不均匀 | 较均匀 |
| 代码密度 | 高 | 低 |
| 硬件复杂度 | 高 | 低 |
| 功耗 | 高 | 低 |
| 编译器要求 | 简单 | 复杂 |
| 流水线支持 | 困难 | 容易 |
| 适用场景 | 通用计算 | 高性能计算 |
| 代表架构 | x86, VAX | ARM, MIPS, RISC-V |

🎯**计算重点**：CISC和RISC的性能评估
- **指令密度**：CISC指令平均执行时间 vs RISC指令数
- **时钟频率**：RISC通常可达更高频率
- **CPI**：RISC平均CPI更低
- **功耗效率**：RISC在移动设备中优势明显

## 4.5 指令执行流程

### 4.5.1 指令周期

指令周期是指从取指令到执行完成的全过程。

#### 基本阶段：
1. **取指周期(Fetch)**：从内存中取指令
2. **译码周期(Decode)**：分析指令操作码
3. **执行周期(Execute)**：执行指令操作
4. **访存周期(Memory)**：访问内存读写数据
5. **写回周期(Writeback)**：将结果写回寄存器

#### 指令周期时序：
```
┌─────────┬─────────┬─────────┬─────────┬─────────┐
│  取指   │  译码   │  执行   │  访存   │  写回   │
└─────────┴─────────┴─────────┴─────────┴─────────┘
```

### 4.5.2 微操作

每个周期由一系列微操作组成。

#### 取指周期微操作：
1. PC → MAR：程序计数器内容送地址寄存器
2. MemRead：发出内存读信号
3. M → IR：内存数据送指令寄存器
4. PC + 1：程序计数器递增

#### 执行周期微操作（以ADD指令为例）：
1. IR → MAR：指令地址字段送地址寄存器
2. MemRead：读操作数
3. M → MDR：操作数送数据寄存器
4. ACC + MDR → ALU：累加器与操作数相加
5. ALU → ACC：结果送累加器

### 4.5.3 指令执行时间计算

**基本公式**：
$$T_{instruction} = \sum_{i=1}^{n} T_{cycle_i}$$

其中：
- $T_{instruction}$：指令执行时间
- $T_{cycle_i}$：第i个时钟周期时间
- n：指令包含的时钟周期数

**考虑内存访问时间**：
$$T_{instruction} = T_{fetch} + T_{decode} + T_{execute} + T_{memory} + T_{writeback}$$

其中：
- $T_{fetch}$：取指时间
- $T_{decode}$：译码时间  
- $T_{execute}$：执行时间
- $T_{memory}$：访存时间
- $T_{writeback}$：写回时间

## 4.6 微指令与微程序

### 4.6.1 微程序控制原理

**微程序控制**是一种用程序方法控制计算机操作的技术。

#### 基本概念：
- **微指令**：控制一个微操作序列的指令
- **微程序**：微指令的有序集合
- **控制存储器**：存放微程序的存储器
- **微地址**：微指令在控制存储器中的地址

#### 微指令格式：
```
┌─────────────┬─────────────┬─────────────┐
│   控制字段   │   测试字段   │   下址字段   │
└─────────────┴─────────────┴─────────────┘
```

#### 微指令类型：
1. **水平型微指令**：并行控制多个微操作
2. **垂直型微指令**：类似机器指令的格式
3. **混合型微指令**：结合水平和垂直特点

### 4.6.2 微程序设计

#### 微程序设计步骤：
1. **分析机器指令**：确定每条机器指令的微操作序列
2. **设计微指令**：为每个微操作设计微指令
3. **安排微程序**：将微指令组织成微程序
4. **设计控制逻辑**：实现微程序的控制逻辑

#### 微程序控制器结构：
- **控制存储器(CM)**：存放微程序
- **微指令寄存器(MIR)**：当前微指令
- **微地址形成逻辑**：产生下一条微指令地址
- **时序发生器**：产生时序信号

## 4.8 典型例题

### 例题1：寻址方式分析
**题目**：某计算机指令格式如下：
```
┌─────────┬─────────────┬─────────────┐
│  操作码  │    Reg     │    Addr     │
└─────────┴─────────────┴─────────────┘
```
其中Reg字段为4位，Addr字段为12位。分析以下寻址方式的有效地址：
1. Reg = 0000, Addr = 0x100
2. Reg = 0101, Addr = 0x200
3. Reg = 1010, Addr = 0x300

**解答**：
1. 寄存器寻址：EA = R0 = 0x100
2. 寄存器间接寻址：EA = (R5) = 0x200
3. 基址寻址：EA = (R10) + 0x300

### 例题2：扩展操作码设计
**题目**：设指令字长16位，地址码长度可变，设计扩展操作码：
- 4位操作码的指令：最多4条
- 8位操作码的指令：每条可扩展出多少条？
- 12位操作码的指令：每条可扩展出多少条？

**解答**：
- 4位操作码指令：使用4位操作码，12位地址码，最多4条
- 8位操作码指令：操作码8位，地址码8位，每条可扩展出2^(16-8) = 256条指令
- 12位操作码指令：操作码12位，地址码4位，每条可扩展出2^(16-12) = 16条指令

### 例题3：指令执行时间计算
**题目**：某计算机时钟频率为1GHz，各操作时间如下：
- 取指：2个时钟周期
- 译码：1个时钟周期  
- 执行：3个时钟周期
- 访存：5个时钟周期
- 写回：1个时钟周期

计算执行一条访存指令的总时间。

**解答**：
总时钟周期数 = 2 + 1 + 3 + 5 + 1 = 12个时钟周期
时钟周期时间 = 1/1GHz = 1ns
总执行时间 = 12 × 1ns = 12ns

**本章重要公式汇总**：

1. **有效地址计算**：
   - 立即寻址：$EA = 立即数$
   - 直接寻址：$EA = A$
   - 间接寻址：$EA = M[A]$
   - 寄存器寻址：$EA = Reg[R]$
   - 寄存器间接寻址：$EA = M[Reg[R]]$
   - 相对寻址：$EA = PC + D$
   - 基址寻址：$EA = Reg[B] + D$
   - 变址寻址：$EA = Reg[X] + D$
   - 基址变址寻址：$EA = Reg[B] + Reg[X] + D$

2. **指令执行时间**：
   $$T_{instruction} = \sum_{i=1}^{n} T_{cycle_i}$$

3. **扩展操作码数量**：
   $$N_{opcode} = \sum_{i=1}^{k} (2^{m_i} \times n_i)$$
   其中$m_i$为第i类指令的操作码位数，$n_i$为对应的指令条数。
