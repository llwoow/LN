# 第六章 总线与输入输出系统

## 6.1 总线概述

### 6.1.1 总线的基本概念

**🔥高频考点** 总线是计算机各部件之间传送信息的公共通道，是连接计算机各个功能部件的纽带。

总线具有以下特点：
- **共享性**：多个部件共享同一总线资源
- **分时性**：同一时间只能有一个主设备使用总线
- **双向性**：数据可以在总线上双向传输

### 6.1.2 总线的分类

#### 按传送信息的类型分类

| 总线类型 | 功能 | 传送方向 |
|---------|------|----------|
| **数据总线** | 传送数据信息 | 双向 |
| **地址总线** | 传送地址信息 | 单向（CPU→外设/内存） |
| **控制总线** | 传送控制与状态信号 | 双向 |

#### 按连接部件层次分类

- **内部总线**：CPU内部寄存器与ALU之间的连接
- **系统总线**：CPU与内存、I/O之间的连接
- **通信总线**：计算机系统之间的连接

### 6.1.3 总线性能指标

#### 💯必考内容：总线带宽计算

**总线带宽**是单位时间内总线可以传送的数据量，计算公式为：

$$Bandwidth = Width \times Frequency$$

其中：
- Width：总线宽度（位）
- Frequency：总线时钟频率（Hz）

**实战计算示例**：
- 32位总线，时钟频率33MHz
- 带宽 = 32 bit × 33 × 10^6 Hz = 1056 × 10^6 bit/s = 132 MB/s

**更精确的带宽计算**：

$$B = \frac{f_{bus} \times W}{8} \text{ (单位：B/s)}$$

其中：
- $f_{bus}$：总线时钟频率（Hz）
- $W$：数据线宽度（bit）

#### 总线延迟模型

**💯必考内容** 总线延迟由以下部分组成：

$$T_{total} = T_{propagation} + T_{arbitration} + T_{transfer} + T_{processing}$$

其中：
- $T_{propagation}$：传播延迟 = 距离 / 信号传播速度
- $T_{arbitration}$：仲裁延迟 = 固定延迟 + 动态延迟
- $T_{transfer}$：传输延迟 = 数据量 / 带宽
- $T_{processing}$：处理延迟

#### 总线利用率

**🎯计算重点** 总线利用率定义为：

$$U = \frac{T_{data}}{T_{data} + T_{overhead}}$$

其中：
- $T_{data}$：有效数据传输时间
- $T_{overhead}$：总线开销时间（仲裁、地址、控制等）

**有效带宽**：
$$B_{effective} = U \times B_{theoretical}$$

## 6.2 总线仲裁

### 6.2.1 仲裁的基本概念

**🔥高频考点** 总线仲裁是在多个主设备竞争总线时，确定哪个设备获得总线使用权的过程。

#### 仲裁的基本要求
- **公平性**：所有设备都有获得总线的机会
- **优先级**：高优先级设备应优先获得总线
- **效率**：仲裁过程不应占用过多时间

### 6.2.2 集中仲裁方式

#### 1. 链式查询方式（菊花链）

**工作原理**：
- 所有设备通过一条共享的"总线请求"线向仲裁器发送请求
- 仲裁器通过"总线授权"线依次查询设备
- 优先级由设备在链中的位置决定

**优点**：
- 结构简单，只需少量控制线
- 优先级固定，硬件实现容易

**缺点**：
- 优先级固定，低优先级设备可能长期等待
- 链式结构可靠性低，任何一个节点故障都会影响后续设备

#### 2. 计时器定时查询方式

**工作原理**：
- 仲裁器包含一个计数器
- 计数器从0开始递增，依次查询各设备的请求状态
- 设备地址与计数值匹配时获得总线使用权

**优点**：
- 优先级可以通过编程改变
- 响应时间可预测

**缺点**：
- 需要更多控制线
- 计数器增加了硬件复杂度

#### 3. 独立请求方式

**工作原理**：
- 每个设备都有独立的"总线请求"和"总线授权"线
- 仲裁器根据优先级策略决定授权哪个设备

**优点**：
- 响应速度快
- 优先级灵活可编程
- 可靠性高

**缺点**：
- 控制线数量多（2n条，n为设备数）
- 硬件复杂度高

#### 仲裁算法性能分析

**⚡易错点** 不同仲裁方式的性能特点：

| 仲裁方式 | 响应时间 | 控制线数量 | 优先级灵活性 | 可靠性 |
|---------|----------|-----------|-------------|--------|
| 链式查询 | 中等 | 少（3条） | 固定 | 低 |
| 计时器查询 | 中等 | 中等（$\lceil log_2 n \rceil + 2$条） | 可编程 | 中等 |
| 独立请求 | 快 | 多（2n条） | 灵活可编程 | 高 |

**性能分析**：
- **响应时间**：独立请求 < 链式查询 ≈ 计时器查询
- **硬件复杂度**：链式查询 < 计时器查询 < 独立请求
- **扩展性**：独立请求最差（控制线数量随设备数线性增长）

**实际应用场景**：
- 链式查询：小型系统，设备数量少
- 计时器查询：中型系统，需要可编程优先级
- 独立请求：大型系统，对响应时间要求高

### 6.2.3 分布式仲裁

**了解内容** 分布式仲裁没有中央仲裁器，每个设备都有自己的仲裁逻辑，通过总线进行仲裁信息的交换。

## 6.3 总线定时

### 6.3.1 同步定时方式

**🔥高频考点** 同步定时方式使用统一的时钟信号来控制总线上的数据传输。

**特点**：
- 所有设备都使用同一个时钟信号
- 数据传输在时钟的上升沿或下降沿进行
- 时序关系简单明确

**优点**：
- 控制简单，时序关系固定
- 传输速度快
- 适用于距离短、速度高的场合

**缺点**：
- 时钟偏移问题（不同设备接收时钟的时间差）
- 缺乏灵活性，难以适应不同速度的设备

### 6.3.2 异步定时方式

**🔥高频考点** 异步定时方式不使用统一的时钟，通过握手信号来协调数据传输。

**握手协议**：
- **请求（Request）**：主设备发出的传输请求
- **响应（Acknowledge）**：从设备发出的响应信号

**优点**：
- 适应性强，可以连接不同速度的设备
- 没有时钟偏移问题
- 可靠性高

**缺点**：
- 控制复杂，需要握手信号
- 传输速度相对较慢

### 6.3.3 半同步定时方式

**了解内容** 半同步定时方式结合了同步和异步的优点，使用时钟信号但允许设备通过等待信号来适应不同的速度。

## 6.4 输入输出系统概述

### 6.4.1 I/O系统的基本概念

**🔥高频考点** 输入输出系统是计算机系统的重要组成部分，负责计算机与外部世界的信息交换。

**I/O系统的组成**：
- **I/O设备**：键盘、显示器、磁盘等
- **I/O接口**：设备控制器、适配器
- **I/O软件**：设备驱动程序、操作系统I/O管理

### 6.4.2 I/O设备的分类

#### 按信息交换单位分类
- **字符设备**：以字符为单位进行数据交换（如键盘、打印机）
- **块设备**：以数据块为单位进行数据交换（如磁盘、磁带）

#### 按数据传输方向分类
- **输入设备**：将外部信息输入计算机
- **输出设备**：将计算机信息输出到外部
- **输入输出设备**：既可输入也可输出（如磁盘）

### 6.4.3 I/O接口的基本功能

**🔥高频考点** I/O接口是CPU与I/O设备之间的桥梁，主要功能包括：

- **数据缓冲**：解决CPU与设备速度不匹配问题
- **信号转换**：电平转换、串并转换等
- **时序控制**：协调CPU与设备的工作时序
- **状态检测**：检测设备的工作状态
- **命令解释**：解释并执行CPU发来的命令

## 6.5 I/O控制方式

### 6.5.1 程序查询方式（Programmed I/O, PIO）

**💯必考内容** 程序查询方式又称程序轮询方式，CPU通过执行程序来控制I/O操作。

**工作原理**：
1. CPU向I/O设备发出命令
2. CPU不断查询设备状态
3. 设备就绪后进行数据传输
4. 传输完成后CPU继续执行后续程序

**特点**：
- CPU与设备串行工作
- CPU利用率低
- 硬件结构简单

**适用场景**：低速设备、简单系统

### 6.5.2 程序中断方式

**💯必考内容** 程序中断方式在设备就绪时主动通知CPU，CPU可以与设备并行工作。

**中断处理流程**：
1. **中断请求**：设备向CPU发出中断请求信号
2. **中断响应**：CPU完成当前指令后响应中断
3. **保护现场**：保存CPU当前状态
4. **转中断服务程序**：执行中断处理程序
5. **恢复现场**：恢复CPU之前保存的状态
6. **中断返回**：继续执行被中断的程序

**中断响应时间计算**：

$$T_{response} = T_{current} + T_{save} + T_{vector}$$

其中：
- $T_{current}$：完成当前指令的时间
- $T_{save}$：保存现场的时间
- $T_{vector}$：获取中断向量的时间

**中断总时间**：

$$T_{interrupt} = T_{response} + T_{save} + T_{ISR} + T_{restore}$$

其中：
- $T_{ISR}$：中断服务程序执行时间
- $T_{restore}$：恢复现场的时间

**适用场景**：中低速设备、需要及时处理的场合

### 6.5.3 DMA方式（Direct Memory Access）

**💯必考内容** DMA方式允许外设直接访问内存，无需CPU干预数据传输过程。

**DMA传输过程**：
1. **DMA请求**：外设向DMA控制器发送数据传输请求
2. **总线请求**：DMA控制器向总线仲裁器请求总线使用权
3. **总线授权**：仲裁器授权DMA控制器使用总线
4. **数据传输**：DMA控制器直接在内存和外设之间传输数据
5. **传输完成**：DMA控制器释放总线，发送中断通知CPU

**DMA传输时间计算**：

$$T_{transfer} = \frac{Data_{size}}{DMA_{bandwidth}} + T_{setup} + T_{complete}$$

其中：
- $Data_{size}$：要传输的数据量
- $DMA_{bandwidth}$：DMA控制器的传输速率
- $T_{setup}$：DMA初始化时间
- $T_{complete}$：传输完成处理时间

**CPU干预时间**：
$$T_{CPU} = T_{setup} + T_{complete}$$

**适用场景**：高速设备、大批量数据传输

### 6.5.4 通道方式

**💯必考内容** 通道是专门的I/O处理器，能够执行通道程序来控制I/O操作。

**通道的特点**：
- 独立的指令系统（通道指令）
- 能够执行I/O程序
- 支持多设备并行操作
- CPU干预最少

**通道类型**：
- **字节多路通道**：连接多个低速字符设备
- **选择通道**：连接高速块设备
- **成组多路通道**：结合前两者优点

**适用场景**：大型系统、多设备并行操作

### 6.5.5 I/O方式对比

**💯必考内容** I/O控制方式的对比分析：

| 控制方式 | CPU干预程度 | 传输效率 | 硬件复杂度 | 适用设备类型 |
|---------|------------|----------|-----------|-------------|
| **程序查询** | 很高 | 低 | 低 | 低速设备，简单系统 |
| **程序中断** | 中等 | 中等 | 中等 | 中低速设备，实时系统 |
| **DMA** | 低 | 高 | 高 | 高速设备，大数据量 |
| **通道** | 很低 | 很高 | 很高 | 大型系统，多设备并行 |

**选择原则**：
- 根据设备速度选择合适的控制方式
- 考虑CPU的利用率要求
- 权衡硬件成本和系统性能

## 6.6 中断系统

### 6.6.1 中断的基本概念

**🔥高频考点** 中断是CPU在执行程序过程中，因发生某种随机事件而暂停当前程序，转去执行相应处理程序的过程。

**中断的基本类型**：
- **硬件中断**：由外部设备发出的中断请求
- **软件中断**：由程序执行中断指令产生的中断
- **异常**：CPU内部产生的错误或特殊情况

### 6.6.2 中断优先级

**⚡易错点** 中断优先级确定原则：

1. **硬件优先级**：通过硬件连线确定优先级
2. **软件优先级**：通过软件设置确定优先级
3. **动态优先级**：优先级可以动态改变

**优先级判别方法**：
- **查询法**：CPU依次查询各中断源
- **硬件判优**：使用优先级编码器
- **软件判优**：使用查询程序

### 6.6.3 中断屏蔽

**🔥高频考点** 中断屏蔽是通过设置中断屏蔽字来禁止某些中断源的中断请求。

**屏蔽字的作用**：
- 禁止低优先级中断
- 保护关键代码段不被中断
- 实现中断嵌套控制

### 6.6.4 中断嵌套

**🔥高频考点** 中断嵌套是指在处理一个中断的过程中，又响应另一个中断请求的情况。

**嵌套规则**：
- 高优先级中断可以中断低优先级中断
- 同优先级中断不能相互中断
- 中断服务程序应保护现场

## 6.7 DMA传输

### 6.7.1 DMA控制器的基本结构

**🔥高频考点** DMA控制器是实现DMA方式的核心部件，主要包含以下部件：

- **地址寄存器**：存放内存地址
- **字计数寄存器**：存放要传输的字节数
- **控制寄存器**：存放传输控制信息
- **状态寄存器**：存放传输状态信息

### 6.7.2 DMA传输方式

**💯必考内容** DMA传输主要有三种方式：

#### 1. 停止CPU访问方式
- DMA传输期间CPU完全停止访问内存
- 传输效率最高
- CPU利用率最低

#### 2. 周期挪用方式
- DMA利用CPU不访问内存的周期进行传输
- 平衡了传输效率和CPU利用率
- 适用于CPU与DMA交替访问内存的情况

#### 3. 交替访问方式
- 将内存周期分为两部分，一部分给CPU，一部分给DMA
- 适用于CPU和DMA都需要频繁访问内存的情况

### 6.7.3 DMA传输过程

**💯必考内容** DMA传输的完整过程：

1. **预处理**：CPU向DMA控制器设置传输参数
2. **数据传送**：DMA控制器控制数据传输
3. **后处理**：DMA传输完成后发送中断通知CPU

## 6.8 I/O编址方式

### 6.8.1 独立编址（I/O映射）

**💯必考内容** 独立编址方式为I/O设备分配独立的地址空间，与内存地址空间分离。

**特点**：
- I/O地址空间独立
- 需要专门的I/O指令
- 不占用内存地址空间

**优点**：
- I/O指令功能简单，执行速度快
- 内存地址空间不受影响
- 译码逻辑简单

**缺点**：
- 指令系统复杂
- I/O指令功能有限
- 需要额外的控制信号

### 6.8.2 统一编址（存储器映射）

**💯必考内容** 统一编址方式将I/O端口映射到内存地址空间中。

**特点**：
- I/O端口占用内存地址空间
- 使用内存操作指令访问I/O设备
- 地址空间统一管理

**优点**：
- 指令功能强大，编程灵活
- 不需要专门的I/O指令
- 内存操作指令都可用于I/O操作

**缺点**：
- 占用内存地址空间
- 地址译码复杂
- 需要区分内存访问和I/O访问

### 6.8.3 两种编址方式对比

**💯必考内容** I/O编址方式的对比：

| 编址方式 | 地址空间 | 指令类型 | 控制信号 | 译码复杂度 |
|---------|----------|----------|----------|-----------|
| **独立编址** | 独立 | 专用I/O指令 | 需要IOR/IOW信号 | 简单 |
| **统一编址** | 统一 | 内存操作指令 | 不需要 | 复杂 |
