# NIST SP 800-125A 虚拟化安全技术内容提取报告

## 文档基本信息
- **标题**: Security Recommendations for Server-based Hypervisor Platforms
- **作者**: Ramaswamy Chandramouli
- **总页数**: 39页
- **文档类型**: NIST特殊出版物
- **版本**: Rev. 1

## 核心内容摘要

### 1. Hypervisor安全机制与最佳实践

#### 1.1 硬件辅助虚拟化安全
**安全建议 HY-SR-2**: 虚拟化主机的硬件应为指令集和内存管理提供虚拟化辅助功能（使用MMU），因为硬件支持提供以下安全保证：

- **内存管理控制**: 更好的内存管理控制可以防止缓冲区溢出攻击
- **IOMMU功能**: IOMMU的DMA重映射功能提供更好的I/O设备隔离
- **直接设备分配**: 直接为特定VM分配I/O设备并启用对这些资源的直接访问，消除了为该VM提供仿真设备驱动程序的需要，从而减少了可信代码的大小
- **处理器模式隔离**: 客户机OS代码和hypervisor代码在不同的处理器模式下执行，提供更好的隔离
- **特权级隔离**: 特权级隔离可以为设备访问调解功能提供更好的保护，基于硬件的内存保护可以提供更好的VM级保护
- **全虚拟化支持**: 通过支持全虚拟化，商用OS版本可以比在准虚拟化平台上运行的修改或移植版本更容易进行修补和更新

#### 1.2 可信引导和测量启动环境(MLE)
**安全建议 HY-SR-1**: 启动的hypervisor应该是包含以下内容的平台和整体基础设施的一部分：

- 支持MLE的硬件，具有基于标准的加密测量能力和存储设备
- 证明过程，具有提供从硬件到所有hypervisor组件的信任链的能力
- 测量的元素应至少包括：核心内核、内核支持模块、设备驱动程序和hypervisor的本地管理应用程序
- 信任链应提供保证，即所有测量的组件未被篡改且其版本正确

#### 1.3 VM内存分配调度选项
**安全建议 HY-SR-3**: Hypervisor应具有为每个需要保证物理RAM的VM指定保证物理RAM的配置选项，以及此值的限制和优先级值，以便在多个VM之间竞争RAM资源时获得所需的RAM资源。此外，默认情况下应禁用允许所有VM的总配置内存超过主机物理RAM的over-commit功能。

#### 1.4 VM CPU分配选项
**安全建议 HY-SR-4**: Hypervisor应具有为所有托管VM配置虚拟资源的强大配置功能，使其不超过关键物理资源（如CPU核心数）。

**安全建议 HY-SR-5**: Hypervisor应提供为每个部署的VM指定CPU时钟周期下限和上限的功能，以及为每个VM指定优先级分数的功能，以便在多个VM竞争CPU资源的情况下促进调度。

### 2. 虚拟机隔离技术与方法

#### 2.1 设备虚拟化安全
**安全建议 HY-SR-6A (仿真)**: 由于通过软件仿真硬件设备的复杂性，除了遭受性能损失外，还会增加TCB的大小，特别是在客户机OS具有本机设备驱动程序且设备仿真代码作为内核模块与hypervisor具有相同特权级别运行的情况下。因此，仿真应仅用于复杂度可管理的情况。

**安全建议 HY-SR-6B (准虚拟化)**: 在VM中使用准虚拟化设备驱动程序的情况下，应通过在专用VM中运行后端设备驱动程序来启用对物理设备的访问调解，而不是在hypervisor中运行。这有助于在低于hypervisor的特权级别运行后端设备驱动程序代码。

**安全建议 HY-SR-6C (直通或自虚拟化硬件设备)**: 在需要为VM提供对DMA能力设备的专用访问的情况下，hypervisor平台应包括I/O内存管理单元(IOMMU)形式的硬件支持，用于验证和转换设备对主机内存的所有访问。

#### 2.2 设备访问控制
**安全建议 HY-SR-7**: 应该可以设置访问控制列表(ACL)来限制每个VM进程对仅分配给该VM的设备的访问。

**安全建议 HY-SR-8**: 应该可以为每个VM设置网络带宽和I/O带宽（例如磁盘读/写速度）的资源限制，以防止拒绝服务(DOS)攻击。

### 3. 虚拟化攻击面分析

#### 3.1 主要攻击向量
根据文档分析，虚拟化平台的主要攻击面包括：

1. **VM逃逸攻击**: 恶意VM访问属于其他VM的内存区域
2. **侧信道攻击**: 涉及一些隐式共享硬件资源（如CPU缓存和转换后备缓冲区）
3. **缓冲区溢出攻击**: 来自虚拟化主机上驻留的VM
4. **设备驱动攻击**: 恶意或被入侵的设备驱动程序
5. **管理接口攻击**: 对hypervisor管理接口和API的攻击

#### 3.2 硬件安全特性
- **IOMMU**: 提供对VM逃逸攻击的安全保护，通过DMA重映射功能
- **扩展页表(EPT)**: 防止从为数据存储保留的内存位置执行代码，从而防止缓冲区溢出攻击
- **硬件虚拟化扩展**: 提供两种执行模式：主机或根模式以及客户机或非根模式

### 4. 虚拟化安全配置建议

#### 4.1 VM镜像管理
**安全建议 HY-SR-9**: 必须为所有类型的VM定义黄金标准，不符合标准的VM镜像不应允许存储在VM镜像服务器或库中。VM镜像库中的镜像应定期扫描过时的OS版本和补丁。

**安全建议 HY-SR-10**: 存储在镜像服务器中的每个VM镜像都应附加数字签名作为真实性和完整性的标记，使用可信、强大的加密密钥签名。

**安全建议 HY-SR-11**: 通过VM镜像库检入和检出镜像的权限应通过强大的访问控制机制强制执行，并仅限于授权的管理员集。

**安全建议 HY-SR-12**: 访问存储VM镜像的服务器应始终通过安全协议（如TLS）进行。

#### 4.2 VM实时迁移
**安全建议 HY-SR-13**: 在VM实时迁移过程中，必须使用安全的身份验证协议；执行迁移的管理员的凭据仅传递给目标主机；内存内容和处理器状态的迁移应通过安全网络连接进行；并在源主机和目标主机中使用专用虚拟网络段来承载此流量。

#### 4.3 VM监控和安全策略执行
**安全建议 HY-SR-14**: 应有用于VM操作的安全监控和安全策略执行的机制——检测在VM内运行的恶意进程以及进出VM的恶意流量。

**安全建议 HY-SR-15**: VM的安全监控和安全策略执行解决方案应基于"VM外部"并利用hypervisor的虚拟机内省功能。通常，此类解决方案涉及在安全加固或可信VM中将安全工具作为安全虚拟设备(SVA)运行。

**安全建议 HY-SR-16**: 在虚拟化主机中运行的所有反恶意软件工具（例如病毒检查器、防火墙和IDPS）应具有定期执行自主签名或参考文件更新的能力。

#### 4.4 细粒度VM管理权限
**安全建议 HY-SR-18**: VM管理的访问控制解决方案应在权限分配级别和对象级别（即权限目标的规范可以是单个VM或基于功能或位置的VM的任何逻辑分组）具有粒度能力。此外，应该存在拒绝VM组内某些特定对象（例如运行特定敏感级别工作负载的VM）权限的能力，尽管具有对VM组的访问权限。

### 5. 集中化管理
**安全建议 HY-SR-19**: 企业中所有hypervisor安装的管理应使用企业虚拟化管理系统(EVMS)集中执行。不同类型工作负载和集群的企业黄金标准hypervisor配置必须通过EVMS进行管理和强制执行。

### 6. 管理网络安全
**安全建议 HY-SR-20**: 应通过分配专用物理NIC来确保hypervisor主机和软件管理功能的保护，如果不可行，则将hypervisor的管理接口放置在专用虚拟网络段中，并使用防火墙强制执行流量控制。

### 7. 相关安全威胁与防护措施

#### 7.1 主要威胁
1. **VM逃逸**: 恶意VM尝试访问其他VM的内存或资源
2. **侧信道攻击**: Spectre和Meltdown等CPU级性能优化攻击
3. **设备驱动漏洞**: 恶意或被入侵的设备驱动程序
4. **配置漂移**: VM配置偏离安全基线
5. **供应链攻击**: 恶意VM镜像或模板

#### 7.2 防护措施
1. **零信任架构**: 实施微分段和细粒度访问控制
2. **硬件安全特性**: 利用IOMMU、VT-x/AMD-V等硬件虚拟化特性
3. **持续监控**: 部署安全虚拟设备进行实时监控
4. **加密和签名**: 对VM镜像和配置进行数字签名
5. **最小权限原则**: 实施细粒度的管理权限控制

### 8. 平台特定指导

文档涵盖了以下主要虚拟化平台的安全配置要点：
- **VMware ESXi**: 锁定模式、证书管理、日志审计
- **Microsoft Hyper-V**: 受防护虚拟机、Credential Guard、主机资源保护
- **KVM/QEMU**: libvirt、SELinux/AppArmor、QEMU安全选项
- **Xen**: Domain0/DomainU、XL/XM工具栈、PCI直通、PV驱动

### 9. 运营与流程建议

#### 9.1 配置管理
**安全建议 HY-SR-17**: VM配置管理工具应具有编译日志并在检测到任何被监控VM中的配置更改时向管理员发出警报的能力。

#### 9.2 变更管理
- 实施变更审批流程
- 配置漂移检测和纠正
- 自动化配置基线检查

#### 9.3 监控和审计
- 集中化日志收集和分析
- 实时安全事件监控
- 定期安全评估和渗透测试

## 总结

NIST SP 800-125A Rev.1提供了全面的虚拟化安全指导，涵盖20项核心安全建议，涵盖以下五个基础功能领域：

1. **HY-BF1**: VM进程隔离
2. **HY-BF2**: 设备调解和访问控制
3. **HY-BF3**: 从客户机VM直接执行命令
4. **HY-BF4**: VM生命周期管理
5. **HY-BF5**: hypervisor平台管理

该文档强调硬件辅助虚拟化的重要性，提供了详细的配置建议，并针对现代虚拟化环境中的各种威胁提供了具体的防护措施。对于任何部署服务器虚拟化的组织来说，这些都是必须遵循的关键安全实践。
